# Security policy

Do not include secrets, credentials, private keys, customer data, private repository content, or sensitive transcripts in an issue or pull request.

For a non-sensitive defect, open a regular GitHub issue. For a vulnerability or accidental disclosure, use GitHub's private vulnerability reporting option when it is available for this repository. If no private channel is available, contact the repository owner through their GitHub profile before sharing details.

Automated public-safety checks detect a small set of common problems. They do not make a contribution safe to publish; every change still requires human review.
